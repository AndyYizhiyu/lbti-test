# LBTI 恋爱行为类型测试产品设计文档

## 1. 定位摘要

LBTI 是 `Love Behavior Type Inventory` 的缩写，定位为“面向恋爱与婚恋市场的轻科学、强传播自测”。它不是临床心理诊断，也不声称判断一个人是否“适合恋爱”，而是用可解释的亲密关系维度，帮助用户看见自己在恋爱中的启动方式、依恋反应、边界需求、表达习惯、筛选策略和关系维护风险。

产品需要同时满足三件事：

- 科学依据：底层参考成人依恋、Sternberg 爱情三角理论、Big Five 与关系满意度、伴侣沟通与冲突修复研究。
- 实用价值：结果页给用户可执行建议，包括如何聊天、如何约会、如何识别自己容易翻车的位置。
- 流量传播：题面和人格名保留 SBTI 式荒诞表达，吸收“恋爱脑、纯爱战士、西格玛男人、慢热女生、理工直男”等网络语料，但把“捞女、绿茶婊”等高攻击词转译为中性行为描述。

## 2. 参考资料拆解

### 2.1 B 站 SBTI 的可复刻机制

`docs/sbti_bilibili_version_info.md` 的核心价值不在“人格内容本身”，而在产品结构：

- 题量轻：30 道常规题 + 少量触发题，用户能在短时间完成。
- 维度多：15 个细分维度，每个维度 2 题，最后合成 L/M/H 档位。
- 计算简单：选项值为 1/2/3，维度总分转 L/M/H，再与人格 pattern 做距离匹配。
- 文案强：题目和人格文案以极端、夸张、网络化语言制造截图传播点。
- 结果弹性：常规人格之外有隐藏人格和兜底人格，制造“彩蛋感”。

可借鉴：题库梗化、人格 pattern 匹配、隐藏人格、结果页可分享。  
不建议照搬：过度辱骂式人格命名、与恋爱主题无关的题目、仅 2 题判断一个维度导致稳定性不足。

### 2.2 16Personalities 的可借鉴机制

16Personalities 的中文站把复杂人格模型包装为三步：完成测试、查看详细结果、释放潜力。它的启发是：

- 首页先卖“被理解感”，不是先讲模型。
- 题目采用同意度量表，用户作答负担低。
- 结果用类型、百分比、详细描述、关系建议共同构成“可信感”。
- 它使用类似 MBTI 的字母表达，但理论上吸收 Big Five 的维度思想，说明“传播友好”和“科学解释”可以分层。

LBTI 应采取相同策略：页面上讲“恋爱里的你为什么这样”，底层再展示维度与建议，不把学术术语堆给用户。

### 2.3 中文婚恋热梗的吸收原则

调研关键词包括恋爱脑、西格玛男人、纯爱战士、直男、理工男、捞女、绿茶婊、慢热女生等。它们不能同等使用：

- 适合直接做传播素材：恋爱脑、纯爱战士、慢热、直球、理工男式汇报、已读不回侦探、西格玛。
- 适合转译后使用：捞女、绿茶婊、养鱼、吊着、情绪价值榨汁机。
- 不适合作为官方人格名：带有强性别羞辱、把一类人污名化、可能激化两性对立的词。

推荐表达方式：


| 网络语料   | 产品内转译            | 可用场景         |
| ------ | ---------------- | ------------ |
| 恋爱脑    | 高投入、低自我稳定、强关系聚焦  | 题目、隐藏人格、翻车提醒 |
| 纯爱战士   | 高承诺、高真诚、低暧昧策略    | 隐藏人格、优势文案    |
| 西格玛男人  | 高边界、低主动、低关系依赖    | 人格名、分享梗      |
| 直男/理工男 | 直给表达、任务化恋爱、低暗示识别 | 题目场景、沟通建议    |
| 捞女     | 资源敏感、交换导向、风险识别   | 避坑维度，不做人身标签  |
| 绿茶婊    | 模糊边界、社交策略、暧昧管理   | 风险场景，不做人格名   |
| 慢热女生   | 低启动、高观察、信任建立慢    | 维度解释、结果建议    |


## 3. 科学依据到 LBTI 维度的映射

LBTI v2 底层建议使用 10 个维度，每个维度 4 题。每题使用 `A/B/C` 三个差异化行为选项，不再使用所有题相同的 1-5 同意度文案。这样用户不是在重复点“像/不像”，而是在具体恋爱场景里选择自己更可能采取的行为。


| 维度          | 测什么               | 科学依据               | 高分解释           | 低分解释          |
| ----------- | ----------------- | ------------------ | -------------- | ------------- |
| D1 恋爱投入度    | 心动后愿意投入多少情绪与行动    | Sternberg 的激情与承诺   | 认真、上头、愿意经营     | 克制、观察、慢进入     |
| D2 依恋安全感    | 对关系稳定性的基本信任       | 成人依恋理论             | 信任关系，不易灾难化     | 容易患得患失、脑补     |
| D3 边界与融合    | 亲密关系中需要多少个人空间     | 依恋回避、亲密需求          | 边界清楚，保留自我      | 喜欢黏合、共享生活     |
| D4 关系主动性    | 是否愿意主动推进关系        | 外向性、社交启动           | 主动破冰、推进约会      | 慢热、观望、等信号     |
| D5 表达真实度    | 真实需求能否说出口         | 伴侣沟通研究             | 直给、明确、少猜谜      | 委婉、试探、怕破坏气氛   |
| D6 冲突修复力    | 冲突后能否复盘和修复        | 亲密关系冲突研究           | 愿意沟通、修复连接      | 冷处理、翻旧账或逃避    |
| D7 现实筛选力    | 识别不匹配和风险的能力       | Big Five 责任心、择偶决策  | 清醒、看行为、不只看感觉   | 容易理想化或被情绪带走   |
| D8 自我价值稳定度  | 是否容易被关系定义自我       | 自尊、神经质与关系满意度       | 不靠对方反馈证明自己     | 容易因对方态度自我怀疑   |
| D9 资源与公平敏感度 | 如何看待恋爱中的付出、金钱和资源  | 社会交换理论、公平理论         | 看重互惠、公平、长期责任   | 更随性或更容易被资源叙事带走 |
| D10 暧昧边界识别  | 对养鱼、吊着、暧昧越界的识别与处理 | 关系承诺、边界管理、风险知觉     | 能识别模糊关系和越界信号   | 容易自我说服或卷入拉扯   |


结果页应显示 10 个维度雷达或条形图，并给每个维度 L/M/H 三档解释：

- L：该维度偏弱或偏低，不等于差，代表当前更少使用这类策略。
- M：弹性区间，会根据对象、阶段和安全感变化。
- H：该维度偏强，既是优势，也可能在极端时变成风险。

维度分档文案建议：


| 维度          | L                           | M                           | H                            |
| ----------- | --------------------------- | --------------------------- | ---------------------------- |
| D1 恋爱投入度    | 心动也会先踩刹车，感情不是不能谈，是启动前要先看路况。 | 会投入，但会给自己留余地，属于“能爱也能撤”的弹性区。 | 一旦认定就容易全功率输出，爱意像开了性能模式。      |
| D2 依恋安全感    | 关系里警报器很灵，已读不回都可能触发灾难预案。     | 大多数时候能稳住，偶尔也会被不确定感拉去加班。     | 比较相信关系本身，不会因为一点风吹草动立刻判死刑。    |
| D3 边界与融合    | 更享受高融合关系，喜欢把对方纳入自己的生活内圈。    | 亲密和独立都要一点，边界会跟对象和阶段一起调整。    | 个人空间是刚需，再喜欢也不能把生活合并成一个压缩包。   |
| D4 关系主动性    | 慢热观望居多，喜欢等信号足够明确再行动。        | 有机会会推进，但不会为了恋爱强行冲刺。         | 主动性强，喜欢把好感从聊天推进到真实相处。        |
| D5 表达真实度    | 习惯先照顾气氛，真实需求经常穿着隐身衣出场。      | 会表达，也会看场合，直说和委婉之间来回切换。      | 需求和态度比较明确，不喜欢把恋爱谈成猜谜综艺。      |
| D6 冲突修复力    | 冲突后容易冷处理、逃避或在心里反复扣分。        | 愿意修复，但需要合适时机和对方也配合。         | 能把争吵拉回问题本身，愿意复盘、道歉和重新连接。     |
| D7 现实筛选力    | 容易被感觉带着走，对明显风险会先开柔光滤镜。      | 既看感觉也看现实，偶尔清醒，偶尔上头。         | 会看长期行为、边界和匹配度，不太吃短期话术。       |
| D8 自我价值稳定度  | 对方态度容易影响自我评价，关系反馈像情绪遥控器。    | 有自己的重心，但遇到重要对象时仍会波动。        | 不太靠恋爱证明自己，单身或恋爱都能保持基本稳定。     |
| D9 资源与公平敏感度 | 对付出和资源不太敏感，容易“开心就好”或事后才觉得不平衡。 | 知道公平重要，但也会看阶段、关系和具体处境。      | 对钱、时间、情绪劳动和承诺投入都很敏感，不喜欢单向供血。 |
| D10 暧昧边界识别  | 容易替暧昧找理由，觉得“TA 可能只是还没想清楚”。  | 会观察，也会给合理解释，不急着贴标签。         | 对养鱼、吊着、越界信号很敏感，闻到一点茶味就会开窗通风。 |


## 4. 四轴类型系统

为了让结果可传播，10 个维度再合成 5 条主轴，每条主轴两个端点，共 32 个主类型。这样比 16 型更丰富，也能容纳“纯爱、清醒、边界、主动、市场敏感”等恋爱市场里的差异。


| 主轴  | 端点 A               | 端点 B                | 由哪些维度决定              |
| --- | ------------------ | ------------------- | -------------------- |
| 热度轴 | H：Heart-first 心动优先 | C：Clear-minded 清醒校准 | D1 恋爱投入度、D7 现实筛选力    |
| 距离轴 | F：Fusion 融合亲密      | B：Boundary 边界独立     | D2 依恋安全感、D3 边界与融合    |
| 表达轴 | D：Direct 直球表达      | S：Soft 柔性缓冲         | D5 表达真实度、D6 冲突修复力    |
| 启动轴 | A：Active 主动推进      | W：Wait 慢热观察         | D4 关系主动性、D8 自我价值稳定度  |
| 市场轴 | M：Market-aware 市场清醒 | N：No-game 低博弈真诚     | D9 资源与公平敏感度、D10 暧昧边界识别 |


主轴计算建议：

- `heatAxis = D1 + (24 - D7)`，高于中位为 H，否则 C。
- `distanceAxis = (24 - D3) + D2`，偏融合为 F，偏边界为 B。实际实现时需根据 D3 题目方向统一校准。
- `expressionAxis = D5 + D6`，高直给/高修复为 D，低直给/偏委婉为 S。
- `initiativeAxis = D4 + D8`，高主动且自我稳定为 A，否则 W。
- `marketAxis = D9 + D10`，高分为 M，代表更重视公平、边界和风险识别；低分为 N，代表更低博弈、更凭感觉和真诚推进。

说明：上述公式是产品 v0.1 版本，后续可通过用户反馈调整权重。

## 5. 计分逻辑

### 5.1 题目结构

- 核心题：40 题，10 个维度各 4 题。
- 彩蛋题：5 题，用于触发隐藏人格，不直接影响主维度。
- 推荐总题量：45 题，预计 6-9 分钟完成。
- 选项形式：`A/B/C` 三选一场景题。每道题的选项文案都应不同，不再复用统一的“像/不像”选项。

选项建议：


| 选项 | 计分建议 | 说明 |
| --- | --- | --- |
| A | 1/2/3 之一 | 每题单独配置，不固定代表低分或高分 |
| B | 1/2/3 之一 | 可作为中间行为，也可作为某种偏向行为 |
| C | 1/2/3 之一 | 文案必须与 A/B 有明显差异 |

题目数据结构建议：

```ts
type QuestionOption = {
  key: 'A' | 'B' | 'C'
  text: string
  score: 1 | 2 | 3
}

type Question = {
  id: string
  dimension: 'D1' | 'D2' | 'D3' | 'D4' | 'D5' | 'D6' | 'D7' | 'D8' | 'D9' | 'D10'
  text: string
  options: QuestionOption[]
}
```


### 5.2 维度分档

每个维度 4 题，每题 1-3 分，总分 4-12：

- 4-6：L
- 7-9：M
- 10-12：H

由于每道题的 `A/B/C` 都单独配置分值，后续编码只需要把所选 option 的 `score` 加入对应维度。

### 5.3 人格匹配

主类型有两种实现方式：

1. 直接五轴切分：根据 5 条主轴得到五字母代码，如 `HFDAM`。
2. pattern 距离匹配：为 32 个主类型设置 10 维 H/M/L pattern，计算用户 10 维向量与人格 pattern 的距离。

推荐 MVP 使用方案 1，原因是结果可解释、实现简单、用户更容易理解。后续可以升级为方案 2，让人格匹配更细腻。

### 5.4 隐藏人格触发

隐藏人格不覆盖主类型，而是在结果页作为“恋爱副人格”显示。这样既能整活，又不会破坏主结果可信度。

触发优先级建议：

1. 安全风险提醒类：低自我价值 + 高投入 + 低安全感。
2. 高传播彩蛋类：纯爱战士、西格玛恋爱绝缘体、已读未回侦探。
3. 趣味类：相亲需求评审官、赛博月老受害者。

## 6. 40 道核心题库蓝图

下面是 v0.2 题库草案。正式实现时每题应带 `id`、`dimension`、`text`、`options`，选项固定为 `A/B/C`，但每题选项文案必须不同。

题目写作规则：

- 每个维度至少 1 道反向题，避免用户一路机械同意。
- 每 4 道题里最多 1 道高强度抽象梗，避免整套测试变成纯段子。
- 题面尽量使用具体恋爱情境，例如消息回复、约会推进、相亲筛选、吵架复盘。
- 题目只测“我通常怎样”，不测“别人是不是坏人”，避免把测试变成伴侣审判器。
- 性别默认中性，用“对方、TA、喜欢的人、恋人”，必要时再提供男女可代入版本。

### D1 恋爱投入度

1. 你刚和一个人聊得很上头，对方说“下次可以一起去那家店”。你会：
  - A：先记下来，但不改自己的安排，看看后续有没有实际推进。`score=1`
  - B：心里有点期待，顺手收藏店铺，但表面保持正常人类语速。`score=2`
  - C：已经开始规划穿搭、路线和见面后的三种可能剧情。`score=3`
2. 对方连续几天主动分享日常，你的内心系统更像：
  - A：收到信号，但还需要更多时间确认这是不是礼貌性营业。`score=1`
  - B：好感增加，会更认真回复，但不会立刻把关系升级。`score=2`
  - C：恋爱 CPU 开始升温，连路边奶茶第二杯半价都像命运暗示。`score=3`
3. 你发现自己喜欢上一个人，接下来最可能：
  - A：先把喜欢放在心里，不让它影响生活主线。`score=1`
  - B：适当增加互动，看看对方是否也愿意靠近。`score=2`
  - C：进入重点项目模式，聊天、见面、投喂、情绪价值同步推进。`score=3`
4. 对方约你周末见面，但你原本打算宅家回血。你会：
  - A：如果不是特别确定喜欢，就还是按原计划休息。`score=1`
  - B：看状态和对方诚意，合适就调整一下。`score=2`
  - C：回血可以下辈子，心动窗口期不能错过。`score=3`

### D2 依恋安全感

1. 对方 5 小时没回你消息，晚上解释说“今天太忙”。你第一反应更接近：
  - A：忙到 5 小时？我的大脑已经自动打开刑侦频道。`score=1`
  - B：能理解，但会观察这种情况是不是经常发生。`score=2`
  - C：如果平时稳定，我会相信这次确实是忙。`score=3`
2. 对方临时取消约会，说身体不舒服。你会：
  - A：嘴上说没事，心里开始怀疑自己是不是不重要。`score=1`
  - B：关心一下，也会看对方后续有没有补偿性安排。`score=2`
  - C：先让 TA 休息，关系不会因为一次变动就塌方。`score=3`
3. 你看到对方给别人朋友圈点赞很频繁。你更可能：
  - A：开始点进主页研究此人是何方神圣。`score=1`
  - B：有点在意，但不会立刻下结论。`score=2`
  - C：只要边界清楚，普通互动不值得开庭审理。`score=3`
4. 对方表达“我最近需要一点自己的时间”。你会：
  - A：听起来像关系降温预告片，心里很难不慌。`score=1`
  - B：会有点失落，但愿意问清楚具体需求。`score=2`
  - C：能接受，每个人都需要整理自己的生活。`score=3`

### D3 边界与融合

1. 恋爱后，对方希望每天睡前固定语音。你会：
  - A：很喜欢，像给关系上了每日签到奖励。`score=1`
  - B：可以，但偶尔太累时希望灵活一点。`score=2`
  - C：固定打卡会让我有压力，我更喜欢自然联系。`score=3`
2. 对方想看你的手机相册和聊天记录，说“情侣之间不该有秘密”。你会：
  - A：如果能让 TA 安心，我可能会配合。`score=1`
  - B：可以解释，但不会把隐私全部交出去。`score=2`
  - C：信任不是开权限，手机不是恋爱体检报告。`score=3`

| MOON 赛博月老受害者 | D4 高、D6 高、自己单身状态可选 | “你撮合别人一套一套，轮到自己开始断网。”   | 少当关系顾问，多给自己创造机会。   |
| TEA 绿茶雷达     | D7 高、彩蛋识别暧昧边界      | “你不骂人，但你闻得到空气里的茶多酚。”    | 识别风险后，用事实而不是标签做判断。 |
| SEA 海王声呐     | D10 高、彩蛋偏识别多人暧昧    | “别人看聊天记录，你看见的是一片海域生态图。” | 别急着审判，先看事实、边界和承诺。 |
| HUNTER 资源猎手   | D9 高、D7 高、D5 高     | “你不是拜金，你只是拒绝把自己活成免费 DLC。” | 重视公平可以，但别把所有真心都换算成成本。 |
| SCUM 渣男渣女避雷器 | D10 高、D2 低、D8 中低   | “你不是敏感，你是被雷劈过之后学会看天气预报。” | 保护自己重要，但别让旧伤替新关系判刑。 |

情绪化人格使用边界：

- 可以在结果页显示“你容易触发某类雷达”，不要写成“你就是捞女/绿茶/渣男”。
- 可以用“茶艺、海王、渣男渣女、资源猎手”等词制造传播张力，但正文必须转回行为描述。
- 不要按性别分配人格。所有副人格都应适用于任何性别。


## 10. 结果页信息架构

结果页建议分 7 块：

1. 顶部人格卡：代码、人格名、匹配度、一句话。
2. 分享摘要：3 行可复制文案，适合朋友圈、小红书、群聊。
3. 10 维度图：显示 L/M/H 与短解释。
4. 恋爱优势：用户看完有“被理解”的正反馈。
5. 翻车预警：指出最可能的关系误区。
6. 实用建议：聊天建议、约会建议、冲突建议、择偶建议。
7. 彩蛋副人格：若触发，则展示隐藏标签和轻量解释。

分享文案模板：

> 我测出来是【{code} - {name}】。  
> 恋爱关键词：{tag1} / {tag2} / {tag3}。  
> 系统建议我：{advice}。  
> 你也测一下，我想看看我们是不是恋爱同频。

## 11. 网站 MVP 页面规划

第一版不需要后端，采用纯前端即可。

- 首页：产品定位、开始测试、科学依据说明、隐私说明。
- 答题页：单题卡片、进度条、上一题/下一题、移动端优先。
- 结果页：人格卡、维度图、建议模块、分享文案。
- 关于页：模型说明、免责声明、参考理论。

推荐技术栈：

- React + Vite + TypeScript。
- 数据放在 `src/data/questions.ts` 与 `src/data/personalities.ts`。
- 计分逻辑放在 `src/lib/scoring.ts`。
- 本地状态使用 React state 或轻量 store，不需要登录。

## 12. 传播设计

传播点不应该只靠“骂得准”，而要靠“又准又好笑”：

- 人格名要像网名：短、可截图、容易自嘲。
- 题目要像评论区：真实婚恋场景 + 荒诞比喻。
- 结果要像朋友锐评：先接住用户，再指出问题。
- 分享卡要给用户保全面子：每个人格都有优点，不把用户打成失败者。

推荐传播标题：

- “测测你在恋爱市场到底是什么物种”
- “你是纯爱战士，还是恋爱产品经理？”
- “别再问 TA 为什么不回消息，先测测你的 LBTI”
- “45 题看懂你为什么总在暧昧里卡住”

## 13. 风险边界

必须避免：

- 把测试包装成心理诊断或情感咨询结论。
- 使用性别羞辱词作为人格名。
- 引导用户对伴侣进行标签化攻击。
- 把“恋爱脑”简单等同于女性，把“理性”简单等同于男性。
- 给出危险关系中的绝对建议，例如“忍一忍”“马上复合”。

建议在首页和结果页加入免责声明：

> LBTI 是基于亲密关系研究启发的娱乐型自测，结果用于自我理解和沟通参考，不构成心理诊断、伴侣评估或婚恋决策建议。如果你正在经历控制、威胁、暴力或严重情绪困扰，请优先寻求现实支持和专业帮助。
